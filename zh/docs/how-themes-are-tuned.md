# 配色怎么调整

[English](../../docs/how-themes-are-tuned.md) · **简体中文**

本页说明哪些颜色和原主题不同、为什么不同，读完就能预判一套主题的样子。文中的对比度都是颜色与其所在底色之间的 WCAG 对比度。

## 从原主题出发

每套主题都以原主题的发布版本为起点，不做预先改动。C Dracula Light、C Moka Light 和 C Pale Light 这三套全新浅色设计，先由对应的深色原主题生成，再走同样的步骤。各套主题对应的原主题见[挑选主题](themes.md#找到你的原主题)。

## 只补缺失

**补全只加原主题没设的颜色，不改原主题设过的任何颜色。**

- 终端、diff、git 标记等 VS Code 原本写死默认值的界面色，取本主题终端色的色相；上面的字至少和 VS Code 默认配色一样易读；默认配色超过 4.5 时，只要求到 4.5。
- 语法规则来自全部原主题合并的规则池，只补在原主题没上色的 scope 上。
- 有些池内规则会借外层 scope 改掉原主题已上色的 token；生成时对样例文件分词实测，查出这类规则就跳过。
- 括号配对色 1–3 用本主题自己的颜色；4–6 和 VS Code 一样不设。
- 原主题没设的终端彩色，按色槽（红、绿、黄等）从它自己的语法色里取，所以 C One Light 的终端黄是它的金棕色 `#986801`。终端底色没设时跟随面板底色，和 VS Code 面板里的终端一致。

## 只修看不清的地方

**文字色和底色里只改出问题的那个，只改到够用，色相与饱和度不变。**

| 对象                           | 下限 |
| ------------------------------ | ---- |
| 正文                           | 4.5  |
| 语法色                         | 4.5  |
| 终端普通色与亮色               | 4.5  |
| 注释                           | 3.4  |
| 终端暗灰（ANSI `90m`）         | 3.4  |
| 选区、查找匹配等高亮底上的正文 | 3.5  |

- 编辑区和输入框选区调到看得出：从原选区色出发，只动必要的一侧。
- VS Code 终端选区从原主题的终端选区色出发，没设时退回编辑区选区色。选区是否看得出、上面的字是否易读，按终端自己的底色与字色检查；不满足要求时，才用本主题的终端蓝重新求色。Terminal.app 的选区单独按配置里的底色与字色检查。
- 当前查找匹配比其他匹配更醒目。
- 界面文字和线条提到与本主题正文相比够读。界面色分为四层：内容（侧栏文字、徽标和按钮上的字）、弱化（行号、输入框占位字）、线条（边框、焦点框）、底色（选中行）。每层的下限相对本主题正文的对比度来定，并用 8 套界面参考主题标定。
- 半透明的颜色先加不透明度，之后只调明度。
- 字色必须由浅转深（或反过来）才能在底色上读清时，改用本主题的编辑区底色或正文色，前提是这样更清楚。例如 C Dracula Dark 粉色徽标上的字变为 `#282A36`。
- 主题没设、由 VS Code 按其他颜色推算的界面色，保持 VS Code 算出的样子。
- 原主题里和所在底色分辨不出的边线与分层底色（OKLab ΔE 小于 0.02）保持原样，原设计本来就没打算画出来；焦点框、选区和当前匹配仍会调到看得出。

## 让不同类的代码分得开

**两类本该区分的代码用了同一种颜色时，其中一类改用本主题里的另一种颜色，直到层次和语法层次最好的 5 套主题一样分明。**

- 这里的「类」指语法角色，例如关键字、函数、字符串、类型、数字、常量、标签和注释。哪两类该区分，取自 25 个主流主题家族：至少 75% 的家族明显区分的，一律区分；其余的只看语法层次最好的 5 套（SynthWave '84、Ayu、Atom One Dark、Noctis 和 Tomorrow Night Blue），至少 3 套区分才区分。
- 检查用 20 段短代码样例，例如 YAML 配置、Shell 脚本和带代码块的 Markdown。两类只要出现在同一段样例里就要分得开，不限于同一行。
- 新颜色一律取自本主题：要么是它的语法里已经用过的颜色，要么是它的 6 个终端彩色（红、绿、黄、蓝、品红、青）调到语法色下限 4.5 后的版本，并且和旧颜色明显不同（CIEDE2000 ΔE 至少 10）。
- 先改常量、内置函数、参数这类次要角色；关键字、函数、字符串、类型和标签通常是主题的标志色，别的改法都不够时才动。本主题的深色或浅色姊妹版层次更好时，新颜色跟随姊妹版：C Owl Light 的字符串改为金色，因为 Night Owl 的字符串是暖桃色。
- 撞色降到这 5 套主题的中位数以内就停，不再继续改。
- 例外是至少 90% 的家族都区分的两类标志色，例如字符串和类型：只要改 token 较少的一类就能分开，就照样分开。所以 C Owl Dark 的类型改为黄色，暖桃色的字符串不变。

## 压低深色主题里的近纯白

深色主题里 `#FFFFFF` 这类近纯白，压到 OKLCH 明度 0.88，色相不变。涉及正文、界面文字、图标和线条、语法色，以及终端白。例如 C Dracula Dark 的正文从 `#F6F6F4` 变为 `#D7D7D6`，C Ayu Dark、C Owl Dark 和 C Pale Dark 的终端亮白从 `#FFFFFF` 变为 `#D7D7D7`。

## 哪些不动

所有主题都不换编辑区底色，除近纯白外不调暗正文，也不降低强调色的饱和度。
