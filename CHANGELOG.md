# Change Log

## v0.0.4 2026-10-15

### Changed

- **Back to the original colors.** v0.0.3 retuned every color (dimmed backgrounds, softer body text, compressed accents, neon and extreme black-and-white removal). Now each theme keeps its original background, body text, syntax, terminal and UI colors, and only colors that are hard to read change, and only as far as needed, keeping hue and saturation: body text, syntax and terminal colors to 4.5 contrast, comments and dim terminal gray to 3.4, line numbers to 2.2, inactive UI text and focus outlines to 3.0, text on badges, buttons and selected rows to 4.5 (the text keeps its light or dark side; the background is nudged slightly first). For example C GitHub Dark and C Dracula Dark are almost identical to their originals, while C Sunlit Light's comments go from 2.5 to 3.4 and its syntax colors from about 3.0 to 4.5.
- Missing pieces are filled in without changing anything the original sets: UI colors VS Code would otherwise hard-code take the hue of the theme's terminal colors, with text at least as readable as VS Code's default (up to 4.5, so light themes' git modified markers are no longer pale yellow); syntax rules from a pool merged from all original themes are added only for scopes the original leaves uncolored, and rules that would recolor a token the original already colors through an outer scope (such as One Light's Less variables) are detected by tokenizing sample files and skipped. Bracket pair colors 1–3 use each theme's own colors; 4–6 stay unset as in VS Code.
- The terminal selection is clearly visible in every theme: each theme now sets `terminal.selectionBackground` and `terminal.inactiveSelectionBackground` (and the Terminal.app profile's selection color) instead of falling back to the faint editor selection. Where body text is only just readable (C Sunlit), selections are made as visible as they can be while text on them stays at 3.5.
- Shorter file names, matching `tools/sources/`: `themes/one-dark.json` instead of `themes/comfort-one-dark-color-theme.json`, `terminal/one-dark.terminal` instead of `terminal/comfort-one-dark.terminal`, and the same for screenshots. Importing a renamed `.terminal` profile creates a profile named `one-dark` and so on; delete the old `comfort-*` profiles in Terminal.app.
- **Breaking:** themes are renamed from `Comfort <Name> Dark` / `Comfort <Name> Light` to `C <Name> Dark` / `C <Name> Light` (for example `C One Dark`), both in the theme picker and as the settings ID. VS Code does not recognize the old names, so after updating, pick the theme again (or change `workbench.colorTheme`, `workbench.preferredDarkColorTheme` and `workbench.preferredLightColorTheme` in `settings.json` to the new names).
- Status colors that VS Code fills in (such as C Dracula's info color) no longer duplicate the warning color.
- Build tools: every color adjustment is a named step in `tools/steps.py` that can be switched on or off (`COMFORT_STEPS`); only the readability steps are on by default. `npm run check` verifies that with every step off the output equals the original plus completion, and gates only on readability (`tools/metrics.py --check`); the full scope x dimension scores (clarity, vivid and soft, fatigue, eye care, blue light) remain as a report (`npm run metrics`).

## v0.0.3 2026-10-12

### Added

- Seven new themes, adapted automatically from their originals and tuned to the same gate: **Comfort GitHub Dark** (from GitHub Dark Dimmed), **Comfort GitHub Light**, **Comfort Dracula Dark** (from Dracula Soft), **Comfort Owl Dark** (from Night Owl), **Comfort Owl Light** (from Night Owl Light), **Comfort Moka Dark** (from One Monokai) and **Comfort Pale Dark** (from Palenight).
- Three newly designed light themes, generated by `tools/design.py` from dark originals and tuned to the same gate: **Comfort Dracula Light** (Dracula's official Alucard palette), **Comfort Pale Light** (Palenight's hues on a pale lavender background) and **Comfort Moka Light** (the classic Monokai palette, its text color `#F8F8F2` as the background, paired with Comfort Moka Dark).
- Terminal.app profiles for Comfort One Dark and Comfort One Light, so every theme now has one.
- Screenshots of every theme in the README (Source Control, code and terminal colors; Explorer and Problems; Search and Output panels).

### Changed

- UI text and icons are no longer harsher than body text: sidebar, file tree, extension list, tab titles, activity bar icons and file-tree git colors used to be near-white in dark themes (up to twice the body text contrast) and near-black in light themes. Badges in dark themes are dimmer colored dots with body-colored text instead of bright blocks.
- All themes retuned for a softer, less tiring look: accents less saturated, comments brighter and tied to body text contrast, dimmer line numbers, body text no harsher than 7.5 (dark) or 8.0 (light) contrast, light backgrounds dimmed to at most 0.80 luminance (no panel, input or widget brighter than 0.85), panels near neutral and highlights no longer glaring. Bright validation, merge and drop backgrounds that used to flash in some panels are fixed.
- **Comfort One Light** now uses the dimmer `#E7E7E9` background.
- Filter boxes and dropdowns (Problems and Output panels, settings) are calm: outlines near-neutral and at most 2.0 contrast (Comfort Owl Dark drew them at 3.7, Comfort Pale Light at 5.1), placeholder text gray and quieter than typed text (2.8–4.2 contrast; Comfort Pale Light's was brighter than the input text), typed text at least 4.5, and focus outlines between 3.0 contrast and 0.8× body text: a focused input no longer looks dimmer than unfocused ones (Comfort Owl and Pale drew the focus outline at 1.0), and Comfort Ayu Dark's gold outline (10.5) is calmer.
- In themes with a tinted background (Comfort Sunlit, Owl and Pale Dark), hover and selection patches VS Code would fill with plain gray (the active activity bar and toolbar icon background, inactive list selections) now take the background's hue instead of looking gray and out of place.
- Layout borders, such as the line between split editors, are no longer glaring: at most 1.6 contrast against the editor (Comfort Dracula Dark / Light drew it at 6.5 and 4.9, Comfort Pale Dark at 2.8).
- Every theme now validates against VS Code's color theme schema: dropped color keys VS Code ignores or has deprecated (renaming those with a successor), made colors that must be translucent translucent again so they no longer cover text, removed token background colors and other ignored token fields, and themed about 80 more UI colors whose defaults were previously missed.
- Syntax rules now come from one shared pool built from all original themes (about 1,300 selectors, many language-specific), each assigned a role and colored with every theme's own role colors, so all themes share the same rich coverage. Theme-specific semantic token colors are dropped in favor of VS Code's built-in semantic-to-TextMate mapping. Ordinary variables get a derived color of their own in every theme, colorful yet clearly apart from parameters, keywords, strings, functions and types.
- Scopes the original themes deliberately dimmed (punctuation, docstrings, embedded delimiters, scopes inside comments and the like), and hand-annotated scopes that were gray in the originals, now use a dimmed, non-bold variant of their role color instead of the full, sometimes bold role color. Where tuning pushed two distinct syntax colors together (for example strings and constants in Comfort GitHub Light, numbers and types in Comfort One Light), they are pulled apart again in lightness, or slightly in hue.
- Markdown reads cleanly in every theme: list items are no longer tinted with the constant color, list markers are a dimmed heading color, headings are always bold, and headings, inline code, links and quotes no longer share a color.
- Calmer workbench: buttons (such as Commit) are low-chroma instead of saturated blocks, badges are quiet low-chroma dots (within 1.7 contrast of the editor, text at 4.5) in dark and light themes alike, list selections (file tree, Problems) are near-neutral with body-colored text, layout borders are neutral, ignored files are dimmed to comment contrast, and sidebar and title bar headings stay readable.
- Terminal colors in dark themes are no brighter than body text (bright colors and white at most 1.2–1.25×), so bright yellow, cyan and white no longer glare; bright colors that turned gray when dimmed get their hue back.
- Branch labels in the Source Control Graph are readable in every theme: their text uses the panel background again (Comfort One Dark carried over light gray text that nearly vanished on the blue label), and label colors are pushed to at least 4.5 contrast against it.
- Less, CSS and SCSS property names are kept clearly apart from property values (Comfort Moka Dark used the same cyan for both).
- Property names in CSS, Less, SCSS, Sass, JSON and TOML get a calm color of their own in every theme: the hue of declaration keywords, dimmed to the quietest syntax level, never bold or italic (they used to share the keyword color, bold in Comfort Sunlit).
- Syntax coverage unified across all themes: the same 33 common scopes (types, namespaces, variables, parameters, object keys, Markdown headings, bold, italic, quotes, links and more) are colored everywhere, borrowing each theme's own color for the nearest role where its original left them out.
- Theme names simplified to `Comfort <Name> Dark` / `Comfort <Name> Light`: One Dark Fit → **Comfort One Dark**, One Light Fit → **Comfort One Light**. Theme files and Terminal.app profiles follow the same `comfort-<name>-dark|light` names, using short one-word names; Comfort Solarized Dark / Light are renamed **Comfort Sunlit Dark / Light**; reselect your theme and re-import the `.terminal` files.

### Removed

- The previous **Comfort One Dark** and **Comfort One Light** were merged into the former Fit themes, which now carry those names.

## v0.0.2 2026-10-08

### Added

- **One Light Fit**: a full eye-comfort adaptation of Atom One Light 2.3.0, designed the same way as One Dark Fit. Background eased from `#FAFAFA` to `#F3F3F3` to reduce glare, comments unified at 3.2, syntax and terminal colors brought to the contrast floor, chroma capped and every hard-coded UI color themed.

### Changed

- **One Dark Fit** (formerly One Dark Pro Lite): reworked from a near-copy of One Dark Pro into a full eye-comfort adaptation. Comments unified at 3.2, syntax and terminal colors brought to the contrast floor, chroma capped and UI text contrast secured; now passes the clarity and eye-comfort gate.
- Comfort theme files and Terminal.app profiles renamed with a `comfort-` prefix; imported Terminal.app profiles now show the full theme name. Re-import the `.terminal` files to pick up the new names.
- **New icon**: a crescent moon and a sun above a row of theme color dots, drawn in the same flat style and accent palette as the other HeavenSky extensions.

## v0.0.1 2026-10-08

Initial release. All seven themes are tuned and adapted for comfort, with palettes designed after the official themes.

### Added

- **One Dark Pro Lite**: One Dark Pro 3.20.2 as a static, settings-free theme with italic and bold enabled.
- **Comfort themes**: One Dark, One Light, Ayu Dark, Ayu Light, Solarized Dark and Solarized Light, tuned for WCAG contrast and capped chroma with reference hues preserved.
- Full UI color coverage in all seven themes, including bracket pairs, the integrated terminal and every color VS Code would otherwise leave at a hard-coded default.
- macOS Terminal.app profiles for the six Comfort themes.
